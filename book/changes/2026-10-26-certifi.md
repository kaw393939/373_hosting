# HOST-003 · Fix a dependency in the application image

[Contents](../../README.md) · [Specification](../../SPEC.md#host-003--companion-image-security-maintenance) · [Validation](../../VALIDATION.md#host-003-companion-image-security-maintenance)

**Status:** application [PR #46](https://github.com/kaw393939/is373-ai-chat/pull/46), full main CI, and development/QA acceptance passed. Production awaits owner-reviewer approval. This instructor worked example adds no required student task.

After HOST-002, the server packages were updated but the preserved chat image
still contained vulnerable `certifi 2026.7.22`. Host maintenance cannot replace
that image's locked Python dependencies. The scoped correction, tests and
release belong to the application repository:

- [Owning issue #44](https://github.com/kaw393939/is373-ai-chat/issues/44) holds acceptance criteria.
- [Dependency requirement](https://github.com/kaw393939/is373-ai-chat/blob/main/docs/requirements.md#dependency-security-maintenance) defines the intended behavior.
- [Canonical certifi change record](https://github.com/kaw393939/is373-ai-chat/blob/main/docs/audit/2026-10-26-certifi.md) records the advisory, reviewed patch and actual evidence.

Use three kinds of evidence. A dependency scan checks known findings against
its database and policy. Local TLS fixtures inside the candidate image check
trusted and rejected connections without a real provider. Development, QA and
production observations establish which digest actually runs. Positive and
negative describe cases; they do not replace unit, integration or browser levels.

Build once and retain the existing production approval gate. Record what was
approved and verify the selected digest afterward. Green CI alone is not proof
of a patched deployment or zero vulnerabilities. Preserve unrelated hosted
services and keep secrets outside Git.

The broader Python/build-tool trust review remains separate in
[issue #45](https://github.com/kaw393939/is373-ai-chat/issues/45).
